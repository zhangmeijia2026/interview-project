> 依据：SRS v1.0（2026-08-31，张帆/刘小娴/张美佳/彭雅奇）。本文把它压缩为可执行口径，并给出**与实装环境的差异裁决表**。

> **2026-09-07 R1–R10 大扩展收口**：在 F01–F08 基础上落地需求 R1 题库/管理模式、R2 薄弱技能库+错题本、R3 简历对比、R4 用户反馈、R9 管理端/LLM 调用审计、R10 本地向量检索（对 question/grade/follow-up 注入 `{knowledge}`，见 `07` §8）；以下 F 表为原始 MVP 分期，R1–R10 扩展见 `10-roadmap.md` 的"扩展 P1–P7"进度。

## 1. 一句话产品

用户上传**个人简历** + 目标**岗位 JD** → 系统做语义匹配、给匹配度与差距 → 生成**面试重点** → **AI 多轮模拟面试**（提问/作答/点评/追问）→ 输出**综合报告**（匹配回顾 + 逐题回放 + 雷达图 + 建议 + 评级）。

主流程（来自 SRS §2.1）：

```
注册登录 → 创建面试 → 传简历(PDF/DOCX) → AI解析简历 → 传/贴JD → AI分析JD
        → 简历-JD匹配 → 生成面试重点 → AI面试(循环) → 综合报告 → 历史管理
```

## 2. 功能模块 F01–F08（范围与优先级）

| 编号 | 模块 | P0（一期必做） | P1/P2（二期或打磨） |
|------|------|---------------|--------------------|
| F01 | 用户注册登录 | 邮箱+密码注册、登录、退出、JWT | 忘记密码(P1)、自动登录(P1)、改资料(P2) |
| F02 | 模拟面试管理 | 创建面试、状态机、列表(按状态筛选) | 删除(P1)、继续面试/中断恢复(P1) |
| F03 | 简历管理 | PDF/DOCX 上传、Tika 提取、LLM 结构化解析、预览确认、存库、≤10MB | 解析进度实时展示(P1) |
| F04 | JD 与智能匹配 | JD 文件/粘贴、LLM 要求提取、简历-JD 多维度匹配、差距、面试重点生成与展示 | 重点可编辑/重新生成(P1) |

## 3. 与 SRS 的差异裁决表（重要）

SRS 写于"PostgreSQL/pgvector + Linux + React 可选"的假设；本组实装环境（2026-09-02 确认）不同，逐条裁决如下：

| # | 主题 | SRS v1.0 原文 | 本体系裁决 | 理由 |
|---|------|--------------|-----------|------|
| D1 | 关系型数据库 | PostgreSQL 14+ | **MySQL 8.3**（服务 `MySQL83` 运行中） | 团队本机已装；SRS 表结构本身是 MySQL 方言（AUTO_INCREMENT/BIGINT），照搬即可 |
| D2 | 向量存储/检索 | PostgreSQL + pgvector | **一期（R10 已落地 2026-09-07）哈希向量**：MySQL JSON 列存 512 维特征哈希向量（`text_chunks` 唯一源），Top-k 命中块以 `{knowledge}` 注入真实 DeepSeek 的 question/grade/follow-up（离线引擎不注入）；默认 `provider=local`，真 Qdrant 已连可切（镜像 `interview_chunks`），缺服务优雅回退 local | MySQL 8.3 无原生 vector；检索语料极小（单用户简历/JD+题库知识点分块数条～数十条），不引外部模型/库即可达目的；方案见 `07` §8/§11 与 `04` §6 |
| D3 | 服务端 OS | Linux(Ubuntu) | **Windows 11**（本机开发/演示）；架构不依赖 OS，部署说明可平移 Linux | 实装环境为 Windows |
| D4 | 前端框架 | React / Vue3 可选 | **Vue3** | 团队选定（TBD-03 关闭） |
| D5 | AI 集成框架 | Spring AI 2.0+ | **Spring AI 1.1.8**（`spring-ai-starter-model-openai`，2026-09-05 落地，经 OpenAI 兼容协议接 DeepSeek） | 取当时稳定 GA 实测落地；"2.0+"写于未来，以工具链实测为真 |
| D6 | LLM 接入 | OpenAI/DeepSeek/通义(可换) | **DeepSeek（`deepseek-chat`）为主**，经 Spring AI OpenAI 兼容接入，保留可换配置 | 成本/效果折中（TBD-01 关闭）；DeepSeek **无 embedding 接口** → 佐证 D2 |
| D7 | 表中"AI集成框架=Claude" | —（未出现） | 澄清：**Claude = Claude Code 开发工具**，不是运行时 AI | 团队原表歧义，Q&A 确认 |
| D8 | 缓存/消息 | Redis + Redisson | **Redis 5.0**；Redisson 分布式锁不用（无多实例），会话状态用 String/Hash | Windows 上的 Redis 5.0 无 RediSearch，够用 |
| D9 | 对象存储 | 本地/MinIO | **本地文件系统**（可配置目录） | MVP 单机足够 |
| D10 | Java/虚拟线程 | Java 17+(支持虚拟线程) | Java **17.0.20.1**，**无虚拟线程** → 依赖 Tomcat 默认线程池 + 明确异步边界 | 虚拟线程需 JDK21；50 并发由 max-threads 支撑，见 `05` §7 |
| D11 | 面试状态机 | 见 SRS §6.1 | 与 SRS 一致：`draft/resume_uploaded/jd_uploaded/matched/ready/in_progress/completed/abandoned` | 直接沿用 |
| D12 | 匹配算法 | LLM 或 Embedding+LLM(待定) | **纯 LLM 多维度匹配**（技能/经验/学历 + 综合） | TBD-02 关闭（一期），见 `07` §3；R10 起真实 DeepSeek 的 question/grade/follow-up 另注入本地向量检索 `{knowledge}`（见 D2/`07` §8），匹配本身仍纯 LLM |

## 4. 必须守住的关键指标（验收口径，来自 SRS §5）

| 指标 | 目标 |
|------|------|
| JD 分析响应 | ≤ 8s（含 LLM） |
| 简历-匹配响应 | ≤ 10s（含 LLM） |
| 面试题首 Token 延迟 | ≤ 5s（P95） |
| 单题点评响应 | ≤ 4s（P95，流式打字机） |
| 简历解析 | ≤ 15s/份（含 LLM 结构化） |
| 并发 | ≥ 50 面试请求并发 |
| 密码 | bcrypt cost ≥ 12 |
| 认证 | JWT：access 2h / refresh 7d |
| 限流 | 面试接口每用户 ≤ 10 次/分钟 |
| 登录锁定 | 连续失败 5 次锁 15 分钟 |
| 传输 | HTTPS(TLS1.2+)；本地演示 HTTP 可临时豁免 |
| 数据 | 不同用户数据严格隔离；文件与 Token 不落明文到前端 | 

> 联调/验收时把上表作为"测试通过线"，映射到 `09` 的用例。
